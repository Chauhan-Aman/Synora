# Synora Engine: Operations & Monitoring Guide

This document outlines everything you need to know to start, monitor, and debug the Synora Engine.

## 1. Complete Startup Sequence

If you ever restart your computer, you need to bring up all 4 components of the system in this order:

### Step 1: Start the Infrastructure (Database & Message Queue)
Open a terminal in the root of the project (`Synora/`) and run:
```bash
docker-compose up -d
```
* **Significance**: This starts **PostgreSQL** (with the `pgvector` extension) which stores all your data, relationships, and embeddings. It also starts **Redis**, which acts as the high-speed memory queue for the background worker.

### Step 2: Start the Local AI
Open a terminal and ensure your local AI is running:
```bash
ollama run llama3.2
```
* **Significance**: This boots up the LLM into your computer's RAM/VRAM. The backend will communicate with this at `http://localhost:11434` to perform extraction and RAG generation. (Ensure you have also run `ollama pull nomic-embed-text` previously for the embedding model).

### Step 3: Start the Backend API & Worker
Open a new terminal, navigate to the API directory, and start NestJS:
```bash
cd apps/api
npm run start:dev
```
* **Significance**: This is the core engine. It exposes the REST API (`/capture`, `/knowledge`, `/chat`), connects to Prisma/Postgres, and starts the **BullMQ Worker** that listens to Redis for new background jobs.

### Step 4: Start the Frontend UI
Open a final terminal, navigate to the Web directory, and start React/Vite:
```bash
cd apps/web
npm run dev
```
* **Significance**: This runs your beautiful glassmorphic UI on `http://localhost:5173`.

## 2. How to Monitor and View your Data

As a system designer, visibility into your databases and message queues is critical. Here is how you can peer into the "black box" of your system:

### Viewing the PostgreSQL / Vector Database
The easiest and best way to see your data is using **Prisma Studio**. 
1. Open a terminal and run:
   ```bash
   cd apps/api
   npx prisma studio
   ```
2. Open your browser to `http://localhost:5555`.
3. **What you'll see**: A beautiful web interface where you can click on the `Artifact`, `Topic`, `Entity`, and `Summary` tables. If you look at an `Artifact`, you will literally see the 768-dimensional `[0.012, -0.045, ...]` float array inside the `embedding` column generated by `pgvector`!

### Viewing Redis and BullMQ (Background Jobs)
BullMQ stores its entire queue state inside Redis.
**Option A: Redis CLI (Terminal)**
1. Run: `docker exec -it synora-redis-1 redis-cli`
2. Type `KEYS *` to see all the BullMQ keys (e.g., `bull:capture-processing:wait`, `bull:capture-processing:active`).
3. Type `TYPE bull:capture-processing:1` to see the job data type.

**Option B: RedisInsight (Recommended GUI)**
1. Download **RedisInsight** (a free GUI tool by Redis).
2. Connect it to `localhost:6379`.
3. **What you'll see**: You can visually inspect the exact JSON payloads sitting in the queue waiting to be processed by your background worker.

### Monitoring NestJS and Ollama
- **NestJS**: Keep your API terminal open. Our `logger.log()` statements print exactly when a job starts, when it calls Ollama, and when it successfully inserts into PostgreSQL.
- **Ollama**: You can view Ollama's active models and logs by running `ollama list` or `ollama ps` in your terminal to see how much GPU memory your models are using!
